(The Problem)

Blind Spots,
Then One Screen

Security relied on people noticing problems. Logs stayed on each machine, so incidents surfaced late and nobody had the full picture.

Before

  • Logs checked by hand, one machine at a time
  • Only the operating systems' built-in alerts
  • Incidents found when a user reported them
  • No overall view of the fleet's security

After

  • Every machine's logs collected on one server
  • Suspicious activity flagged automatically
  • Alerts in real time, before anyone calls IT
  • Fleet status, threats and reports on one dashboard

(What I Owned)

  • Scoping. Turned the team's goals into functional and non-functional requirements, then broke the project into five deliverables.
  • Design. Planned the architecture, use cases and deployment, with the security server isolated on its own virtual machine.
  • Rollout. Brought the Wazuh server online and connected Windows and Linux machines to it.
  • Validation. Proved the setup end to end, from agent connection to alerts on the dashboard, and documented it in a 26-page report.

(Part 02)

What the Team
Sees Now

With the agents in place, the IT team can follow six areas of security from one place.

Log analysis

System and application logs from every machine, collected and correlated in one place.

Intrusion detection

Rules and signatures that flag suspicious behavior and access attempts.

File integrity

Changes to critical files and system settings are tracked and reported.

Vulnerabilities

Known weaknesses in installed software, with the patches still to apply.

Real-time alerts

Incidents raised as they happen, with severity, so the team can react right away.

Reports

Dashboards and reports by machine, alert type or severity, to support decisions.
